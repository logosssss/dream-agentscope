# 《AgentScope 落地实战》选题规划

> 最近更新：2026-11-05
> 主线：Java 老兵 → AI Agent 工程师 | 载体：Dream-SaaS 真实项目，不是玩具 Demo
> 代码基线：`main`。每篇发布时打 tag `lesson-NN`，文中 permalink 指向该 tag。
> 当前基线：仓库 `v0.1.0`（`pom.xml` 为 `0.1.0-SNAPSHOT`）。待打 tag：`lesson-01`，发布前执行 `git tag lesson-01 && git push origin lesson-01`。

## 1. 定位

**读者**：写了几年 Spring Boot、正在被公司要求"上个 AI 功能"的 Java 后端。他们不缺 CRUD 能力，缺的是把 Agent 塞进生产系统的那套判断。

**不写**：大模型原理、Prompt 技巧、模型跑分、LangChain 综述。这些不缺人写。

**只写**：项目里实际发生过的问题——哪一个 API 用错会串会话、哪一段流式代码会漏判审核、哪张表少个字段导致额度算错。全部以现象、机制、改法三段式陈述。

**文风**（硬约束）：

| 项 | 要求 |
|---|---|
| 人称 | 不用第一人称（我 / 我们），不用第二人称（你 / 大家）；以无主语句式陈述 |
| 口述感 | 禁止「聊聊」「踩过的坑」「不得不说」「说实话」一类口语 |
| 主观描述 | 不写感受、不写评价、不写推测；只写现象、机制、取值、代价 |
| 允许的例外 | 引用官方文档原话、代码注释、报错原文 |
| 篇幅分配 | 机制与代码 ≥70%，结论 ≤30% |

**差异化**：每篇对应仓库里一段**正在生产跑的代码**，文末给出可运行的 tag，读者能 `git checkout lesson-03` 直接对照。

## 2. 课程地图

不是并列选题，是有先修关系的四条线：

```
第一季 破冰    01 项目总览 → 02 概念地图 → 03 流式生命周期 → 04 工具设计
                                                    │
第二季 RAG     05 入库流水线 → 06 检索降级 → 07 Agentic RAG → 08 RAG 脏活
                                                    │
第三季 编排     09 审批中间件 → 10 多 Agent → 11 记忆与画像
                                                    │
第四季 上线     12 额度限流幂等 → 13 架构收口 → 14 观测与成本
```

前三季每篇都能独立读，但**强烈建议按序**：03 不懂 `streamEvents` 的生命周期，09 的审批流会看不懂。

## 3.1 事实约束

所有文章的内容来源限定为：仓库中的代码、各模块 README、`deploy/` 模板、`docs/` 文档、可复现的命令输出。

| 禁止 | 说明 |
|---|---|
| 编造事故 | 不写"上线首周出现某故障"这类未发生的经历 |
| 编造数据 | 耗时、金额、并发数没有实测值就不写，改用配置默认值 |
| 编造版本 | 版本号只写 `pom.xml` 中的实际值 |
| 夸大能力 | 未实现的功能只能出现在「当前未实现」小节 |

拿不到事实的段落，直接删掉，不补空话。

## 4. 标题规范（公众号）

全系列统一结构：

```
AgentScope 落地实战 NN｜<对象>：<结论或规模>
```

| 位 | 规则 |
|---|---|
| 前缀 | 固定 `AgentScope 落地实战`，不加书名号，便于用户在订阅列表与搜索里识别系列 |
| 编号 | 两位数字 `01`–`14`，全角竖线 `｜` 分隔，不加空格 |
| 对象 | 具体模块、接口或场景，读者能立刻判断与自己是否相关 |
| 结论 | 用数字或对比给确定信息，不写"详解""浅析"这类空词 |
| 长度 | ≤ 64 字（公众号上限），实测值控制在 40–52 字 |

## 5. 单篇产出清单

1. `index.md` —— 母版，唯一事实来源，带 front matter；
2. `csdn.md` —— CSDN 发布稿：母版的**超集**。母版所有小节逐字保留，另加 CSDN 专属小节（配图、代码走读、实现细节）；不放封面图，封面在发布设置里单独上传；
3. `wechat.html` —— 内联样式，全选粘贴进公众号；
4. `assets/` —— 配图 `fig-0N-*.png` 与三张封面；
5. 打 tag `lesson-NN`，回填本文件状态。

`csdn.md` 比母版多出的内容固定为四类，避免两边越写越偏：

| 类型 | 允许加什么 | 不允许 |
|---|---|---|
| 配图 | 架构图、链路图、分层图，脚本产出 `fig-0N-*.png` | mermaid（CSDN 不渲染） |
| 代码 | ≤20 行的关键方法、规则定义、SQL | 整类贴出、与结论无关的代码 |
| 事实 | 类名、包名、默认值、报错原文、表名 | 未经代码核实的推断 |
| 段落 | 机制解释、边界说明、触发条件 | 与公众号重复的铺陈 |

共同小节必须两处一致，改事实时同改。校验方式：公众号版的小节标题必须能在 CSDN 版里找到。

```bash
grep '^## ' docs/tutorial/01-project-overview/index.md | sed 's/^## //' \
  | while read -r h; do grep -q "^## $h$" docs/tutorial/01-project-overview/csdn.md \
  || echo "缺失: $h"; done
```

CSDN 发布信息：

| 字段 | 值 |
|---|---|
| 标题 | 见各篇 front matter 的 `csdn_title`（不带系列前缀，关键词前置） |
| 摘要 | 见 `summary` |
| 标签 | 5 个以内，前两个固定 `AgentScope`、`Java` |
| 专栏 | `AgentScope Java 落地实战：从 RAG 到多 Agent 编排` |
| 封面 | `cover-csdn-1280x720.png`（16:9，1280×720） |

## 8. 专栏简介

CSDN 专栏名：`AgentScope Java 落地实战：从 RAG 到多 Agent 编排`（38 字，关键词前置，便于站内搜索聚合）。

**通用简介（200 字，CSDN 专栏与公众号合集共用）**

> 基于开源项目 Dream-SaaS（Java 21 + AgentScope 2.0.4）的落地实战专栏，代码全部开源，每篇对应一段可 checkout 的真实实现。主线：框架概念与流式生命周期、RAG 从入库到检索降级、多 Agent 编排与审批、额度限流与上线运维。只写实际踩过的坑：哪个 API 用错会串会话、哪张表少字段导致额度算错。适合把 Agent 接入生产系统的 Java 后端工程师。

**短版（129 字，位置受限时用）**

> Java 老兵转 AI Agent 工程师的落地实战。载体是开源项目 Dream-SaaS（AgentScope Java 2.0.4），从 RAG 到多 Agent 编排，只写真实踩过的问题与解法，每篇对应仓库里一段可 checkout 的代码，每周更新。

写作约束：不写"由浅入深""循序渐进"这类空话；必须出现可验证的坐标——项目名、版本号、可 checkout 的实现。改简介时同步核对本文件的季划分，避免简介承诺与篇目顺序脱节。
