# 管理端：基本可观察、可运营

状态：**五块都已落地，未部署、未提交**。不改 `docs/reference/agentscope-architecture-guide.md`。

## 为什么有这一份

管理端 12 个页面已经对着现有接口接上，能停用和恢复、改上限、看运行步骤和这一轮的 token。还回答不了「这个对话用户从哪来、什么时候做了什么」：用户页只有标识、显示名和状态；运行记录没有来源地址；后台操作审计库里有时间，列表没把它查出来。额度流水和本进程就绪有接口，没有页面。

这一轮把观察补到能对上人、时间和来源，运营继续用已经有的写入。不新开执行面。

## 已锁定

| 决定 | 说明 |
| --- | --- |
| 观察对象是对话用户的每一次运行 | 页面对话和 API 对话都写 `agent_run`，来源地址记在这一行上 |
| 住址不收 | 运营对账用不上 |
| 来源地址取 `X-Real-IP` | 现网 Nginx 把 `$remote_addr` 写成这个头。没有该头，或头里不是单一地址时，用连接对端。仍没有就空串 |
| 不采用 `X-Forwarded-For` | 最左段由调用方自己带，能伪造 |
| 地址在请求线程上抄走 | 流式返回 Flux 之后不再读 `HttpServletRequest`。抄下来的字符串跟着这一轮进 `RunLog` |
| 用户页按租户加人跳到运行 | 运行列表增加可选 `tenantId`，和已有的 `userId` 一起 AND。只按用户会把别的租户里同名用户混进来 |
| 直接打开运行页时租户可空 | 空串不当成查询条件，和现有 `userId` / `sessionId` 一样 |
| 老运行没有来源地址 | 新列可空。接口把空值收成空串，页面显示「—」 |
| 列表和详情都显示来源地址 | 详情不按用户过滤，运维仍按运行号看别人的失败 |
| 管理端操作人不加地址 | 操作人仍是手填的 `X-Operator-Id`，缺省 `admin`。这一轮只把 `operation_audit.created_at` 查出来并显示 |
| 用户行补登记时间和更新时间 | `tenant_user` 已有这两列，摘要和页面没带。不在用户行上记 IP |
| 额度页展示已有流水 | `GET /api/admin/quota-usage` 已要求租户。页面选定租户后列出最近流水。不读 Redis 里的剩余额度 |
| 壳层展示本进程就绪 | `GET /health/ready` 不带管理令牌，内容是管理进程自己的 MySQL、Redis、Milvus。不代理用户进程 |
| 条数收口不变 | 列表仍走现有上限，默认 50，最多 100。不做游标分页，不做导出 |

## 现状（不再重做）

这些页面和写入已经可用，本规划不改它们的业务规则：

| 页面 | 已有能力 |
| --- | --- |
| 租户 | 登记、停用、关闭、恢复 |
| 用户 | 按租户登记、停用、恢复 |
| 额度 | 每日请求、每日 token、每日费用、同时运行的登记和改上限 |
| 模型 | 配置启停、再插一行价格 |
| 审计 | 安全干预、后台操作、执行事件。执行事件已有时间 |
| 运行 | 按请求号、用户、会话、状态查列表；详情有步骤、审计事件、token 与金额 |
| 保留 / 调度 / 评测 / 工具 | 登记、停用、恢复。不执行清理、不触发、不调模型、不跑工具 |
| 账单 | 草稿、确认、开票、付款。不重算金额 |
| 删除 | 批准或拒绝请求。不执行删除 |

## 五块顺序

### 1. 运行的来源地址，以及按租户进人

状态：已落地。迁移 `V50__agent_run_client_ip.sql`。来源地址在 `ClientIp` 里解析，对话入口在请求线程上抄走后写入 `agent_run.client_ip`。运行列表增加 `tenantId`，用户页链到 `/runs?tenantId=&userId=`。

下一号迁移是 `V50__agent_run_client_ip.sql`：

```sql
ALTER TABLE agent_run
    ADD COLUMN client_ip VARCHAR(45) NULL COMMENT '来源地址。没有则为空' AFTER request_id;
```

`VARCHAR(45)` 够一条 IPv6。不建索引，列表不按地址筛。

接入层新增一个纯函数，只做这三步：头是单一地址就用它；否则用 `getRemoteAddr()` 里的单一地址；否则空串。含逗号、空白或长过 45 的头视为没有。

`ChatAppService` 和 `ApiChatAppService` 在进入对话时（仍在请求线程）抄下这个字符串，经 `SessionTurn.finish`、`TurnRecorder.complete`、`RunLog.complete` 传到 `MysqlRunLog`。`AbsentRunLog` 继续跳过。调度不写 `agent_run`，没有地址可记。

写入放进 `insertFinished`。`search` 与 `findByRunId` 的 SELECT 带上 `client_ip`。`RunRow` / `RunDetail` 增加 `clientIp`，空值收成空串。

`GET /api/admin/runs` 增加可选 `tenantId`。`AgentRunMapper.search` 在非空时 `AND tenant_id = #{tenantId}`。

`RunsView` 增加来源地址列，并从 `?tenantId=&userId=` 填进筛选。`UsersView` 每一行链到这个查询。筛选条件仍可手改，手改不要求回写地址栏。

测试不连真实 MySQL、Redis。地址解析用假请求。运行查询沿用现有 MyBatis 测试替身，断言租户条件和 `clientIp` 空串。

### 2. 后台操作的时间

状态：已落地。列表查出 `created_at`，审计页「操作审计」最左列显示到秒。登记响应的时间仍是空串，不回读库。不加来源地址，不回填前后快照。

### 3. 用户的登记时间

状态：已落地。用户列表带出 `created_at` 和 `updated_at`，页面显示到秒。对话鉴权的 `findByTenantAndUser` 仍不读这两列。登记入参没变。

### 4. 额度流水

状态：已落地。额度页另选租户后调用 `GET /api/admin/quota-usage`，列出时间、用户、类型、数量、入口。没选租户不发请求。页面按返回的 `quotaType` 显示，文案写明这不是剩余额度。不读 Redis。

### 5. 本进程就绪

状态：已落地。壳层调 `GET /health/ready`，不带管理令牌。200 列出 mysql、redis、milvus；503 仍解析正文，DOWN 标红。这是管理进程自己的检查，不代理用户进程。

## 明确不做

- 用户账号登录进管理端。管理端仍用 `X-Caller-Token` 与手填操作人。
- 批准删除后真删数据，按保留策略清理，管理端触发调度，评测调用模型。
- 在用户行或操作审计上记来源地址。
- 用 `X-Forwarded-For` 当来源。
- 运行全文、导出、超过 100 条的游标分页。
- 从管理端改运行、取消运行、重跑。
- 管理进程去探用户进程的端口或模型。

## 验收

每一块单独验收，通过再做下一块。

| 块 | 通过标准 |
| --- | --- |
| 1 | 页面对话和 API 对话结束后，新运行带上来源地址；伪造的转发头不会被记成地址；老行详情里地址为空串；用户页跳转后的列表同时命中该租户和该用户 |
| 2 | 后台操作列表有时间，顺序仍是新的在前 |
| 3 | 用户列表有登记时间和更新时间，登记入参不变 |
| 4 | 选定租户能看到该租户最近的额度流水；未选租户不发这个请求 |
| 5 | 壳层能看出本进程三项检查是通过还是失败 |

构建从仓库根、JDK 21：`mvn -pl agent-admin -am test`，以及这一块碰到的 `agent-access`、`agent-db` 模块。测试不连接真实 Redis、MySQL、Milvus。前端改动跑 `web-admin` 已有的类型检查。部署另说，不跟规划一起做。
